# 微信手机号登录与资料补全

更新：2026-09-21。AppID 为 `wx3d8dc6fb0e764ec7`，项目配置基础库为 `3.17.1`。本次已完成本地代码、回归和微信模板编译；本任务未执行云部署。最新真机日志已确认手机号在微信原生回调阶段被权限拒绝，详见下节；平台权限开通及真机成功授权仍待复验。

## 本次真机错误与旧版差异

用户提供的记录为 `native_tap` → `native_callback / unavailable / errCode:102`，没有该次授权的 `cloud_request`。这表示微信原生手机号能力拒绝提供授权结果，代码尚未请求云端兑换手机号。旁边的 `private_getBackgroundFetchData` 隐私日志来自另一个接口，不能用来判定本次手机号失败原因；其他请求的 `cloud.callFunction:ok` 也不表示手机号授权成功。

在当前仓库的 Git 基线中，旧登录通过微信 OPENID 恢复账号，注册时手机号可手填。新增流程要求微信验证手机号，因此还依赖这个 AppID 的手机号服务权限。旧版身份登录成功不等于已经开通手机号能力。

管理员需登录同一 AppID 的微信公众平台小程序后台，查看“获取手机号／手机号快速验证”能力的主体资格、开通状态及可用额度，按后台实际提示处理。`102` 已定位到权限拒绝，具体缺少哪项条件还不能从现有日志确定。同步核对手机号用途的隐私指引；不要因为后台预拉取日志而盲目修改隐私配置。能力可用后再次主动授权，预期出现 `native_callback / ok` → `cloud_request` → `cloud_success`。

本次将权限拒绝细分为 `permission_denied`，页面明确提示“当前小程序暂无手机号获取权限，请联系管理员检查服务开通状态”；客户端不支持时提示更新微信。代码改动不会替该 AppID 开通微信平台权限。

## 用户流程

1. 在“我的”点击登录，或从发布／接单功能进入登录页，先显示“微信手机号一键登录”。
2. 用户点击微信原生手机号授权按钮。云端验证手机号后，首次使用者进入必填资料页。
3. 必填昵称、头像、性别、学院、专业、所在校区。昵称使用微信昵称填写能力，头像使用微信头像选择能力，二者都可修改；手机号只读，点击“更换”须重新经过微信授权。
4. 保存后按学校审核规则进入正常使用或等待审核。未验证手机号、资料不完整、审核未通过和停用账号均不能通过订单业务校验。

微信手机号授权不会同时返回昵称或头像。页面通过 `type="nickname"` 和 `open-type="chooseAvatar"` 让用户选择／填写，不能静默读取或替用户同意授权。取消授权后保留登录页，用户可再次主动发起。

旧账号保留原有资料。尚未验证微信手机号的旧账号须先授权；已有完整有效资料的账号授权后可继续使用，缺少必填项的账号进入补全页。不会把数据库中原有手填号码直接标为已验证。

## 接口与约束

| 接口 | 行为 |
| --- | --- |
| `passport/wechat_login` | 接收 `getPhoneNumber` 的一次性 `code`，用云端 `phonenumber.getPhoneNumber` 兑换手机号，返回账号及会话 |
| `passport/register` | 在已验证号码的账号上完成资料，首次完成时执行学校审核政策 |
| `passport/edit_base` | 修改资料并返回更新后的会话，拒绝用表单手填号码替换已验证号码 |
| `passport/login` | 根据云开发可信微信身份恢复会话，附带手机号验证和资料完成状态 |
| `passport/my_detail` | 返回当前账号资料及规范化的验证／完成状态 |

微信身份来自云函数可信 `OPENID`。手机号兑换校验 AppID 水印和中国大陆号码格式，手机号归属在学校范围内通过事务绑定；同校跨校区共用账号，不同学校相互隔离。前端不保存 AppSecret，也不把 `wx.login` 的会话 code 混用为手机号 code。

客户端只对明确发起的授权调用一次手机号接口，不自动重放一次性 code。若保存已提交但回包丢失，补全页重新加载后会先同步会话，再返回原功能；较早的游客请求不能覆盖刚完成的授权。审核拒绝／停用状态不能靠再次授权自行解除。

## 真机点击后只转圈的定位

`private_getBackgroundFetchData:fail` 是微信内部后台预拉取接口的日志，不是 `getPhoneNumber` 的授权结果。项目未主动调用该预拉取接口；不能仅凭此日志认定手机号能力、隐私配置或云函数有问题。

重新编译小程序后，在真机调试控制台筛选 `[wechat-phone-login]`，主动点击一次登录并记录是否出现微信手机号授权窗口。按钮点击埋点不会改变按钮状态，页面加载状态只在原生授权回调后开启；不要在点击时提前禁用原生按钮。

| 诊断记录 | 已知阶段与下一步 |
| --- | --- |
| 只有 `native_tap`，授权窗口已关闭但仍无后续记录 | 点击已到达页面，微信尚未返回授权回调。记录授权窗口是否出现，核实该 AppID 的手机号能力、隐私声明及微信客户端状态；此时不能归因于手机号云函数 |
| `native_callback` / `cancelled` | 用户取消授权，不会调用手机号云接口；可再次主动点击 |
| `native_callback` / `privacy` | 原生手机号回调明确包含隐私相关失败；核对隐私指引与授权状态 |
| `native_callback` / `permission_denied` | 原生回调为 `102` 或明确提示权限不足；核对小程序后台手机号服务资格、开通状态和额度。旧版诊断把这类错误记为 `unavailable` |
| `native_callback` / `unsupported` | 原生接口不支持；更新微信并在真机重新主动授权 |
| `native_callback` / `unavailable` | 其他原生能力不可用；结合平台服务状态继续排查 |
| `native_callback` / `missing_code` 或 `native_error` | 微信未交付有效手机号 code；尚未进入手机号兑换，不会用 `wx.login` 的会话 code 替代 |
| `native_callback` / `ok`，随后 `cloud_request` | 已收到手机号 code，客户端开始准备／发起云请求。还需查看后续结果；前置校区初始化也可能在这一阶段失败 |
| `cloud_failure` / `environment_missing`、`function_missing`、`timeout` | 分别检查云环境配置、最新 mcloud 是否存在／部署完成、网络及云端耗时。单次云调用已有默认 20 秒超时，不会自动重放手机号 code |
| `cloud_failure` / `cloud_error` | 查看页面业务错误，以及同一时间 mcloud 的 `passport/wechat_login` 请求日志；若路由不存在，说明云端版本未包含新接口 |
| 云端 `phone_exchange_failure` | 已进入微信手机号兑换但 OpenAPI 拒绝；根据数值 `errCode` 核对权限、服务状态或 code 有效性。此记录需要部署最新 mcloud 才会出现 |
| `cloud_success` | 客户端已收到验证手机号后的会话；接下来由页面处理资料补全或返回业务。该记录本身不表示资料已完善或审核已通过 |

新增诊断只记录固定阶段、固定分类和数值错误码，不记录手机号、一次性 code、token、微信身份或完整 SDK 错误。反馈时提供这些记录即可。失败回调会停止页面加载，并显示短提示和持续可见的页面错误；微信根本未回调时不能伪造一次“授权失败”或假定用户已同意。

## 接入真实环境

- 使用有该 AppID 开发权限的微信账号登录微信开发者工具。仅填写 AppID 不会授予工具账号、云环境或手机号服务权限。
- 确认小程序后台的手机号获取能力可用、额度可用，并配置与手机号／头像用途相符的隐私保护指引。是否具备服务资格及实际费用以该小程序后台为准，本地测试不能验证这些条件。
- 明确测试云环境后，同步更新 `cloudfunctions/mcloud` 和小程序。`mcloud/config.json` 已声明 `phonenumber.getPhoneNumber`，云端安装锁定依赖并核对该权限实际生效。
- 多校版本仍须按 [多校部署与迁移手册](MULTI_TENANT_ROLLOUT.md) 更新配套函数、规则和历史数据。不要混用旧的后端快照与新的登录页面。
- 本机开发工具 CLI 需要访问其用户目录中的 `.cli` 文件。当前沙箱未放行此目录；`cli islogin` 目录访问升级请求及浏览器验证均被自动审批服务的 `404 / unsupported codex-auto-review` 错误阻断。因此未执行真实开发工具联调、浏览器窄屏测量或真实手机号授权；需恢复审批服务并放行本机调试权限后继续。

## 真机待验收

| 场景 | 预期 |
| --- | --- |
| 新账号同意／拒绝手机号授权 | 同意后进入补全；拒绝后不创建可用会话、不进入业务 |
| 缺少任一必填项、直接重放业务请求 | 页面提示补全，云端也拒绝发布／接单 |
| 选择微信昵称和头像、手动修改昵称 | 成功保存并在“我的”展示，重新进入仍保留 |
| 更换微信授权手机号 | 更新已验证号码，保留未保存的昵称等草稿，旧号码不能由过期表单写回 |
| 学校开启注册审核 | 提交后等待审核，管理员通过前不能开展业务 |
| 原有账号登录、停用或审核拒绝账号重试 | 完成验证后保留原资料；授权本身不能绕过审核／停用 |
| 弱网回包丢失、快速刷新和重复点击 | 不重复兑换同一手机号 code；已成功保存可恢复，旧回复不覆盖新状态 |
| 同校跨校区、跨学校使用相同号码 | 同校号码归属唯一，学校之间互相隔离 |
