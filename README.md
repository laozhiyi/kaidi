# GXNU校跑

基于微信小程序和云开发的 GXNU校跑应用，支持快递代取、物品代送、商品代买。当前使用双方线下结算，平台不代收费用。

## 功能入口

| 入口 | 功能 |
| --- | --- |
| 首页 | 选择服务、填写并发布订单、查看公告 |
| 订单 | 可接单、我的接单、我的发布、已完成；取件、送达凭证、确认收货、异常处理 |
| 我的 | 微信登录与个人资料、退出登录、注销账户、常用联系人和地址、收藏、评价与信誉、申诉、邀请 |
| 消息中心 | 公告、订单与处理通知，未读筛选、全部已读、详情跳转和微信订阅 |
| 校区客服 | 联系方式及在线留言 |
| 管理后台 | 订单、用户、申诉、公告、客服、价格、营业和履约设置、报表、运行监控、学校与校区配置 |

所有页面以 [app.json](miniprogram/app.json) 为准，云端接口以 [route.js](cloudfunctions/mcloud/project/crun/public/route.js) 为准。

## 订单进度

顶部进度对应五个实际动作：发布 → 接单 → 取件（代买为购齐）→ 送达 → 完成。每个节点依据自己的时间字段、履约事件或明确的当前状态显示，详情列出已记录的时间；等待时间、预计送达时间不会自动推进进度。

管理员直接完结订单不会补出未发生的取件、送达。旧订单缺少历史时间时明确显示未记录；异常、取消、过期显示各自状态。详情和订单列表在收到订单更新信号后刷新。

## 注册与常用资料

- 点击“点击微信登录”打开头像／昵称弹层，确认后直接进入个人资料；联系资料始终展开。头像和昵称由微信原生控件填写，手机号授权默认关闭，发布／接单仍需联系资料及审核，详见 [登录与账户](deployment/WECHAT_LOGIN.md)。
- 退出撤销服务端会话并清理本地资料。注销成功即退出，两小时内主动登录会取消注销；等于截止时间已到期，有任何未完成的发单／接单时拒绝注销。到期数据及可确认归属的私有图片由订单维护任务清理。
- 默认常用地址和联系人自动填入首页、独立下单页；正在编辑的手填内容和已有订单不会被默认资料覆盖。
- 发布成功后清理上一单的备注和包裹，下一单可以使用新的默认资料。常用地址入口可主动重新选择。
- 后台学校／校区授权门槛已取消，管理员账号、角色、令牌及请求的数据范围继续生效；详见 [后台管理](ADMIN_CONSOLE.md)。
- 当前内测界面使用已保存或默认校区；面向多校开放前，按部署手册恢复选择入口并验证切换。

## 安装与更新

1. 用微信开发者工具导入项目根目录，检查 AppID、基础库与目标云环境。
2. 按 [部署与迁移手册](deployment/MULTI_TENANT_ROLLOUT.md) 配置环境、依赖、数据库权限与索引。已有数据先备份并执行相应迁移，不能按空库初始化覆盖。
3. API 部署 `cloudfunctions/mcloud`；从当前源码生成并部署独立订单维护、通知任务。停用旧的 `operations-minute` 触发器，避免旧任务继续运行。
4. 重新编译小程序并生成新的真机预览，检查注册、发布、接单、送达、确认收货和后台保存。

首次空库通过 `INIT_ADMIN_NAME`（默认 `admin`）和至少 12 位的 `INIT_ADMIN_PASSWORD` 初始化管理员，没有默认密码。目标环境使用 `CLOUD_ENV_ID` 显式指定；初始化后移除初始密码变量。

修改本地源码不会自动更新云端函数或已经生成的预览码。登录／注销需要配套更新 `mcloud`、从最新源码生成的 `ordersWorker`、账户集合规则与索引，并重新编译小程序；保持 `WECHAT_PHONE_LOGIN_ENABLED` 未设置或为 `false`。旧缓存需要主动登录换取服务端凭证。当前检查不代表已完成云端部署、微信接口权限验证或真机验收。

客户端和管理界面统一显示“GXNU校跑”。微信搜索、分享卡片等使用的小程序注册名称还需在微信公众平台核对／修改；项目标题不会替代平台名称设置。

项目已开启上传时过滤无依赖文件。上传窗口中的“无依赖文件未打包”表示未被当前页面引用的旧组件、模板或工具被排除，不是上传失败；不要为此关闭过滤或强制打包。若代码质量提示“未使用的组件”，应核对页面的 `usingComponents` 和实际 WXML，清理无用注册后重新编译、重新扫描。是否上传成功以开发者工具的最终结果为准。

## 本地检查

在项目根目录执行：

```powershell
npm.cmd test --prefix cloudfunctions/mcloud
node scripts/check-architecture-source.cjs
node scripts/check-miniprogram-pages.cjs --wcc '<微信开发者工具内的 wcc.exe>' --wcsc '<微信开发者工具内的 wcsc.exe>'
```

测试覆盖订单全流程与并发重试、默认资料与发布表单、注册审核、收藏评价申诉、客服、公告通知、后台操作、数据范围、迁移和独立任务。微信编译器另检查模板、样式与页面渲染。本地数据库和微信传输使用测试替身，真实容量、消息投递与手机上的行为需要部署后验证。
