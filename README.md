# 云速取

基于微信小程序和云开发的 云速取应用，支持快递代取、物品代送、商品代买。当前使用双方线下结算，平台不代收费用。

## 功能入口

| 入口 | 功能 |
| --- | --- |
| 首页 | 选择服务、填写并发布订单、查看公告 |
| 订单 | 可接单、我的接单、我的发布、已完成；取件、送达凭证、确认收货、异常处理 |
| 我的 | 微信登录与个人资料、退出登录、注销账户、常用联系人和地址、收藏、评价与信誉、申诉、在线客服、邀请、跑腿结算开通与换卡 |
| 消息中心 | 公告、订单与处理通知、客服回复，未读筛选、全部已读、详情跳转和微信订阅 |
| 在线客服 | 微信内直接和客服对话；所有客服共享一个会话池，谁在线谁接 |
| 管理后台 | 订单、用户、申诉、公告、客服会话与邀请码、价格、营业和履约设置、报表、运行监控、学校与校区配置 |

所有页面以 [app.json](miniprogram/app.json) 为准，云端接口以 [route.js](cloudfunctions/mcloud/project/crun/public/route.js) 为准。

《云速取用户服务协议》和《云速取代取人（骑手）服务与结算协议》的正文在 [agreements.js](miniprogram/projects/crun/public/agreements.js)，由协议页 `pages/about/agreement` 显示。用户协议的入口在登录页按钮下方和「关于我们」；骑手协议在「关于我们」和跑腿结算开通页，开通前须勾选。改协议时更新正文和 `version`，骑手协议还要同步云端的 `CONSENT_VERSION`。

跑腿费（每件及整单）不低于 1 元。界面不写明这个下限：输入框不接受开头的 0 和小数点，后台参考价下限也是 1 元，云端会拒绝更低的金额。

## 订单进度

顶部进度对应五个实际动作：发布 → 接单 → 取件（代买为购齐）→ 送达 → 完成。每个节点依据自己的时间字段、履约事件或明确的当前状态显示，详情列出已记录的时间；等待时间、预计送达时间不会自动推进进度。

管理员直接完结订单不会补出未发生的取件、送达。旧订单缺少历史时间时明确显示未记录；异常、取消、过期显示各自状态。详情和订单列表在收到订单更新信号后刷新。

## 注册与常用资料

- 点击“点击微信登录”完成微信身份登录。资料未完成或联系电话未验证的用户进入个人资料页，在「联系电话」一栏点「获取微信手机号」。云端校验授权号码并绑定到当前账号。已验证且资料完整的用户可直接返回「我的」或原业务页。详见 [登录与账户](docs/WECHAT_LOGIN.md)。
- 提交注册资料后进入待审核（`USER_STATUS=0`）：待审核账号可以先发单，但不能接单；后台审核通过才算注册成功，之后才能接单。审核未过与被停用账号不能发单。
- 退出撤销服务端会话并清理本地资料。注销成功即退出，两小时内主动登录会取消注销；等于截止时间已到期，有任何未完成的发单／接单时拒绝注销。到期数据及可确认归属的私有图片由订单维护任务清理。
- 默认常用地址和联系人自动填入首页、独立下单页；正在编辑的手填内容和已有订单不会被默认资料覆盖。
- 发布成功后清理上一单的备注和包裹，下一单可以使用新的默认资料。常用地址入口可主动重新选择。
- 后台学校／校区授权门槛已取消，管理员账号、角色、令牌及请求的数据范围继续生效；详见 [后台管理](docs/ADMIN_CONSOLE.md)。
- 客服在后台登录页点击「客服首次开通」，输入管理员生成的邀请码并确认。小程序先建立微信会话，再兑换邀请码和开通客服权限。客服开通无需提交学生注册资料。
- 当前内测仅开放广西师范大学雁山校区。个人资料的校区列表会显示同校其他校区及「暂未开放」状态，新发单与接单仅在雁山开放。扩大范围时同步调整 `mcloud` 的 `PUBLIC_CAMPUS_SCOPE` 和个人资料页的 `PUBLIC_PROFILE_CAMPUS`。

## 安装与更新

1. 用微信开发者工具导入项目根目录，检查 AppID、基础库与目标云环境。
2. 按 [部署手册](docs/DEPLOYMENT.md) 配置环境、依赖、数据库权限与索引。已有数据先备份并执行相应迁移，不能按空库初始化覆盖。
3. 上传并部署 `cloudfunctions/mcloud`（云端安装依赖）。订单维护与通知定时器随 `config.json` 一起部署，上传后在控制台确认 `orders-minute`、`notifications-minute` 存在，并删除旧的 `operations-minute` 触发器。
4. 重新编译小程序并生成新的真机预览，检查注册、发布、接单、送达、确认收货和后台保存。

首次空库通过 `INIT_ADMIN_NAME`（默认 `admin`）和至少 12 位的 `INIT_ADMIN_PASSWORD` 初始化管理员，没有默认密码。目标环境使用 `CLOUD_ENV_ID` 显式指定；初始化后移除初始密码变量。

登录、资料页手机号验证和账户注销需要配套更新 `mcloud`、账户集合规则与索引，并重新编译小程序。部署前核对微信公众平台的手机号快速验证权限、额度和隐私保护指引。资料页验证由新版 `mcloud` 启用，原有的手机号登录环境变量可以移除。详见 [部署步骤](docs/WECHAT_LOGIN.md#配套部署)。

客户端和管理界面统一显示“云速取”。微信搜索、分享卡片等使用的小程序注册名称还需在微信公众平台核对／修改；项目标题不会替代平台名称设置。

项目已开启上传时过滤无依赖文件。上传窗口中的“无依赖文件未打包”表示未被当前页面引用的旧组件、模板或工具被排除，不是上传失败；不要为此关闭过滤或强制打包。若代码质量提示“未使用的组件”，应核对页面的 `usingComponents` 和实际 WXML，清理无用注册后重新编译、重新扫描。是否上传成功以开发者工具的最终结果为准。

## 本地检查

在项目根目录执行：

```powershell
npm.cmd test --prefix cloudfunctions/mcloud
node scripts/check-architecture-source.cjs
node scripts/check-miniprogram-pages.cjs --wcc '<微信开发者工具内的 wcc.exe>' --wcsc '<微信开发者工具内的 wcsc.exe>'
```

测试覆盖订单全流程与并发重试、默认资料与发布表单、注册审核、收藏评价申诉、在线客服（共享池会话、邀请码激活、客服接口白名单）、公告通知、后台操作、数据范围、迁移和独立任务。微信编译器另检查模板、样式与页面渲染。本地数据库和微信传输使用测试替身，真实容量、消息投递与手机上的行为需要部署后验证。
