# 校园快递代取：非微信支付版部署与验收手册

更新日期：2026-09-07。

## 1. 当前交付边界

代码补齐了线下结算订单、骑手审核、送达凭证、发布者确认、异常处理、关联投诉、站内消息和运营后台，并保留校园客服聊天。

**未保存运营配置时使用默认开放开关及北京时间 08:00–22:00 营业时间；已保存的暂停状态不自动覆盖。代码通过本地测试不等于已通过微信审核或可直接对外运营。** 本次未连接生产数据库、未部署云函数、未更改云端权限、未执行真实支付/退款、未做双账号真机验收。以下带“上线前”的事项必须在实际环境完成。

### 已实现的核心规则

- 新订单仅为线下结算，服务端计算金额；不代收、不伪造付款状态，不支持微信支付创建或自动退款。
- 订单状态：0 待接单 → 1 配送中 → 2 待发布者确认 → 9 已完成；3 异常处理中，99 已取消。
- 发布者只能取消待接单；已接单的取消请求应进入异常流程。
- 只有审核通过、账号正常且校区匹配的骑手可接单；不可接自己的订单。
- 送达必须上传凭证；只有发布者能确认收货。超时不自动确认、不自动扣信用分。
- 接单时开始计算预计履约时限；接单截止时间采用北京时间，未来最多7天。
- 暂停服务或非营业时间停止发布和接单；已接单的送达、确认、投诉、异常处理仍可执行。
- 用户被停用/失联导致无法发起异常时，管理员可附依据“转异常处理”，核实后恢复、取消或人工完结。
- 并发抢单、订单变更、配额、幂等记录、订单事件、站内通知使用数据库事务。请求ID同内容重试不重复落单，不同内容不可复用。
- 我的接单保留取消/完成历史；“隐藏订单”不是删除证据。管理员不可无说明硬改订单状态。
- 公开列表/详情使用字段白名单，取件码、收件地址、手机、图片凭证只向参与者/已鉴权管理员开放。
- 手机号是自填联系方式，不是微信认证手机号或实名认证。修改姓名/手机号会使已批准骑手进入复审。

## 3. 云环境与初始化

1. 先导出数据库与存储引用清单并保留可恢复备份。测试与生产使用不同云环境、小程序配置。
2. 配置小程序 AppID 和项目实际云环境。检查 miniprogram/setting/setting.js 中的 CLOUD_ID；不要沿用示例环境。
3. 部署 cloudfunctions/mcloud 的代码、依赖及 config.json。服务端优先 CLOUD_ENV_ID/TCB_ENV，否则使用SDK动态当前环境。旧工具方法也读取 CLOUD_ID，因此建议显式设置 CLOUD_ENV_ID。
4. 环境变量见 cloudfunctions/mcloud/.env.example；该文件仅参考，应用不会自动加载 .env。
5. 首次初始化需在云函数环境中设置 INIT_ADMIN_PASSWORD（12至128位且包含字母数字）、可选 INIT_ADMIN_NAME。没有默认弱密码。
6. 首次初始化期间不要开放客户端流量，单实例执行一次并确认管理员与集合创建完成，再开启定时器及测试流量；初始化并发不作为迁移工具。
7. 初始化完成后移除 INIT_ADMIN_PASSWORD 环境变量。不得写入仓库、日志或命令行参数。
8. 核对内容安全API调用权限，生产 CONTENT_CHECK_DISABLED 必须为 false 或未设置；审核不可用时应阻止提交，而不是跳过审核。
9. 后台“运营工作台 → 配置”填写实际校区、价格、件数限制、接单上限、营业时间及线下结算说明。加急默认关闭；开通后必须有真实运力保障。
10. 未保存运营配置时默认 enabled=true；已存在配置必须明确 enabled=true 才开放，保存过的 false 或异常旧配置继续暂停。准备上线或尚未完成第8节验收时，请先在后台关闭“开放服务”并保存。关闭不会中止已接订单履约。

### 旧管理员密码迁移（上线前）

旧MD5密码不再兼容，也不提供MD5回退。必须由有数据库维护权限的人安全重置；仅重设 INIT_ADMIN_PASSWORD 不会覆盖已有安装的管理员。

提供离线脚本 scripts/admin-password-hash.cjs：只生成scrypt散列与撤销会话字段，不连接/修改数据库。以下输入不进入PowerShell命令历史：

~~~powershell
$secret = Read-Host '输入新管理员密码' -AsSecureString
$ptr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secret)
try {
  $env:ADMIN_RESET_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($ptr)
  node scripts/admin-password-hash.cjs
} finally {
  Remove-Item Env:ADMIN_RESET_PASSWORD -ErrorAction SilentlyContinue
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($ptr)
  Remove-Variable secret,ptr -ErrorAction SilentlyContinue
}
~~~

将输出中的四个字段更新至**核对过项目及账号的单个管理员文档**，不要批量覆盖账号；散列也按敏感材料保管。同步清除 ADMIN_TOKEN、ADMIN_TOKEN_USER、ADMIN_TOKEN_TIME，通知管理员重新登录。客户端已移除“记住明文密码”，加载登录页时清理旧 admin-pwd 缓存。

## 4. 数据库权限与迁移（上线硬条件）

### 客户端不能直接读写业务集合

在云控制台为所有业务集合设置客户端直接读写拒绝；仅经可信云函数鉴权读写。不能只依赖页面隐藏按钮或默认“仅创建者可写”。管理员token也不能让客户端直接读 bx_admin。

初始化涉及的集合（默认前缀 bx_）：

- setup、setup_crun、admin、log、news、mail、follow、thing、food、fav、user、feedback、invite；
- campus_service、campus_service_message；
- identity_unique、operation_config、operation_audit、operation_limit；
- order_quota、order_event、order_request、notification、subscription、feedback_request。

### 索引建议

下列是**字段组合建议，不是可直接部署的控制台配置**。以真实查询和控制台索引提示、排序方向为准，建完后实测：

| 集合 | 主要字段组合 |
| --- | --- |
| mail | _pid + MAIL_STATUS + MAIL_PAYMENT_MODE + MAIL_END_TIME（过期/可接单） |
| mail | _pid + MAIL_STATUS + MAIL_DUE_TIME（超时；同时过滤 MAIL_OVERDUE_NOTIFIED） |
| mail | _pid + MAIL_USER_ID + MAIL_ADD_TIME；_pid + MAIL_ACCEPT_USER_ID + MAIL_ADD_TIME |
| mail | _pid + MAIL_STATUS + MAIL_ADD_TIME；校区/金额排序等额外筛选按控制台提示补齐 |
| notification | _pid + userId + createdAt；_pid + delivery + nextAttemptAt |
| feedback | _pid + FB_USER_ID + FB_ADD_TIME；_pid + FB_ADD_TIME |
| user | _pid + USER_RIDER_STATUS + USER_RIDER_APPLIED；_pid + USER_MINI_OPENID |
| operation_limit | _pid + expiresAt |

- 升级前停写，检查同一 _pid + USER_MINI_OPENID 的重复用户，备份后人工合并，迁移其订单/投诉/消息归属。去重后建立用户身份唯一索引。
- 新注册使用确定性文档ID，手机号占用使用 identity_unique 事务锁。旧数据须核查重号、空号与归属后补齐锁记录；不能把自填手机号占用记录当作身份核验。
- order_quota 保存活动订单ID，新用户首次操作会从旧订单初始化配额（最多扫描1000条）。历史数据量大或有异常重复记录时，上线前离线重建配额并核对；不能直接删除配额集合来绕过上限。
- 不自动删除旧订单、投诉、幂等记录和审计证据。不批量把旧支付单标记为线下单。
- 有历史微信支付单的环境必须人工对账，保留原支付标志/流水，退款在原支付渠道处理。订单状态变更不等于资金退款。

## 5. 云存储与证据（上线硬条件）

### 必须配置并实测的访问语义

- 客户端只允许上传到自己 private/<原始微信openid>/ 前缀；不得写入他人前缀。
- 取件截图与投诉/送达图片应为私有资源，禁止其他用户绕过云函数直接读。
- **private-evidence/** 目录所有客户端禁止写入、覆盖和删除，仅服务端可写。
- 图片审核成功后，云函数把已审核二进制复制到 private-evidence/<openid>/<内容散列>.png|.jpg；业务数据引用此副本。原上传者之后改动临时图不能改变已归档证据。
- 编辑只允许复用当前本人订单已有归档图片；不能通过构造fileID引入别人的证据。
- 已鉴权的参与者/管理员由云函数获取有效期300秒的临时地址。必须实测地址在私有规则下可用、未授权用户无法签发，且过期后失效。
- 规则的具体语法依赖实际控制台，本文不提供未经环境验证的可直接部署规则。**不能把“云函数生成了签名URL”当作已设置私有权限。**

签名URL本身属于敏感信息，持有人在有效期内可能转发；技术不能彻底阻止截图转发。不要把URL、取件码、手机号打印到日志或公共分析平台。

目前没有自动清理孤儿上传/归档图，避免误删证据。运营应建立按订单/投诉/完整order_event引用扫描的清理流程、保留期及备份恢复机制；不可按文件年龄直接批量删除。

## 6. 通知与定时任务

- config.json 中 operations-minute：cron 为 0 */5 * * * * *（每5分钟）。请在云控制台确认触发器真正生效，并验证定时任务不能由普通小程序伪造触发。
- 每轮最多30条过期待接单、30条超时订单、30条待投递通知，以及100条过期限流桶。任务积压需监控和扩容；不是无限吞吐队列。
- 过期待接线下单自动取消；已接订单仅提醒，不自动收货。后台有超级管理员手动维护入口。
- 站内消息与订单状态在同一事务落库，投诉回复也产生站内通知。
- 微信订阅需用户主动同意、后台选用的真实模板及 subscribeMessage.send 权限；并非所有人都能收到。
- 设置 ORDER_SUBSCRIBE_TEMPLATE_ID 和 ORDER_SUBSCRIBE_FIELDS JSON，键必须为 order/status/time，值为实际模板字段名。选择能容纳订单短ID、状态文本、北京时间的类型；不能照抄任意示例字段。
- 未配模板不会影响订单，只保留站内消息。配置后需用户重新授权；已跳过的历史通知不会自动补发。
- 投递有事务租约、指数退避、最多3次尝试；用户拒绝类错误不继续重试。提供的是有限重试的至少一次尝试，进程在“发送成功但未记账”时崩溃仍可能重复通知，不承诺外部消息恰好一次。
- 监控 failed通知、异常单、待确认超时、任务最近成功时间、云函数错误率及数据库限额。告警接收人由运营实际配置。

## 8. 发布和回滚顺序

1. 暂停服务并停止旧客户端写入，备份；完成去重、密码迁移、配额核查。
2. 配置数据库/存储权限、环境变量、索引；部署服务端及触发器。
3. 在体验版验证新客户端。旧客户端缺少requestId或使用旧支付接口将被拒绝，这是有意的安全限制。
4. 测试通过后发布客户端，确认旧版本兼容策略，再从运营配置启用服务。
5. 异常时先暂停接单/发布，再回退到兼容新数据结构和安全校验的版本。**不能回滚恢复旧任意改状态、旧无鉴权图片或旧弱密码入口。**

- 发单页配置失败结束加载并展示原因和重试按钮；重试/下拉刷新不清空已填资料。价格、校区、开关配置无效时不允许提交，不使用本地默认价格绕过服务暂停。编辑模式必须先成功读取本人可编辑订单。

- “我的”页使用原生导航栏处理顶部安全区，改为独立样式的等宽卡片，去除负边距叠放，保留个人资料、订单记录、消息、骑手资格、服务与设置入口。
- 订单详情不再等待可选提醒配置；缺失编号、空订单、历史时间格式异常均有明确处理。参与者鉴权后的图片预览失败不再阻塞文字详情，也不会向非参与者开放私密图片或地址。公开详情支持点击重试和返回时刷新。

本地验证：92 项 Node 回归测试通过；48 个注册页面及静态引用检查通过；安装的云 SDK 配置读取/事务封装离线检查通过。个人页在包含全局样式的本地 HTML 等效预览中检查了 320、375、430px 宽度和长昵称，无横向溢出、卡片或头像/文字/箭头重叠；该检查不能代替微信渲染器与真机验收。

### 部署后复验

1. 重新上传并部署 `cloudfunctions/mcloud`（包含这次初始化、媒体预览修复），再重新编译小程序；只编译前端不会更新云端逻辑。
2. 在后台核对运营配置：服务校区、价格、营业时间与启用开关。未保存配置的默认开关现为开放；已保存的暂停状态保持不变，勿误认为只更新前端就能解除云端暂停。
3. 从首页进入发单页；断网后重试；恢复网络确认表单内容保留。分别测试新订单发布与本人待接单订单编辑。
4. 用发布者、骑手和非参与者分别打开订单详情；测试不存在的订单、删除/不可读取的图片、返回详情后状态刷新。
5. 在微信开发者工具及窄屏/刘海屏真机检查“我的”页、底部菜单、安全区、长昵称和账号审核状态。
6. 如仍提示“服务器繁忙”，按实际复现时间查看 `mcloud` 日志中 `operations/config`、`mail/view`、`mail/insert` 对应的 `route`、`errCode`、`errMsg`、`errStack`；排查环境是否一致、云函数是否更新、集合是否可访问。不要通过开放数据库权限或启用默认价格来掩盖错误。

## 10. 发单与订单详情界面整改

### 发单页

- 独立的蓝白卡片设计：校区切换卡、营业状态与时间、三档包裹规格和步进器、取送路线、取件码/截图、联系人、截止时间及补充要求。
- 结算说明改为短提示和点击查看的完整说明；底部固定显示总件数、代取费用及主操作按钮。暂停、休息和配置加载失败不再混为一条无样式提示。
- 没有配置文档时默认开放；**管理员已保存的关闭开关不会被这次代码更新自动打开**。配置读取失败仍阻止发布，不用客户端假价格或默认开关绕过服务端。
- 最多上传6张截图，与服务端限制一致；编辑时保留骑手备注，配置重试保留本页已填信息。暂停期间仍可编辑已有的本人待接单订单。

### 订单详情

- 公开详情和本人订单详情共用 `pages/mail/tpl/mail_detail_tpl.wxml`、`style/mail_detail.wxss`：状态主题与进度、包裹和费用摘要、取送路线、联系卡、取件凭证、送达照片、异常说明、订单信息和动态时间线。
- 底部按角色与状态切换主操作：编辑订单、提交送达凭证、确认收货或联系对方；取消、异常申请、投诉、订阅收入“更多”。取消/确认仍有二次确认，上传与接单有重复点击锁。
- 凭证与异常填写使用底部弹层；送达说明最多300字且至少1张图，异常说明最多500字，均最多6张图。
- 未参与订单者仍无法在界面查看详细送达地址、电话、取件码、照片或操作记录；云端鉴权和DTO脱敏保持不变。未标记线下结算的历史订单提示核对款项，不标示为已付款或直接线下结算。
